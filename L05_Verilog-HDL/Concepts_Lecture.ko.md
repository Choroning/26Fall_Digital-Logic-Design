## 1. 개요

### 1.1 집적회로 설계의 변천 과정

집적회로가 게이트 수백 개 규모에서 수십만 개 이상 규모로 커지면서 설계 방식도 완전히 바뀌었다.

| 측면 | 1960~1970년대 | 1980년대 | 1990년대~현재 |
|:-------|:---------------|:------|:-----------------|
| **설계 방법** | 트랜지스터 수준, 상향식(bottom-up) | 게이트 수준(하향식과 상향식의 결합) | 알고리즘과 기능 수준, 하향식(top-down) |
| **설계 도구** | 레이아웃 편집기 | 회로도(schematic) 편집기 | HDL 합성기 |
| **설계 범위** | 1K 게이트 이하(게이트, 카운터, MUX) | 10K~100K 게이트(마이크로프로세서) | 100K 게이트 이상(고성능 프로세서) |

- **상향식** 설계는 작은 부품(트랜지스터, 게이트)에서 시작하여 이를 더 큰 블록으로 조립한다.
- **하향식** 설계는 시스템 전체의 기능에서 시작하여 이를 단계적으로 더 작은 블록으로 세분한다.
- **레이아웃 편집기**는 칩 위의 트랜지스터의 물리적 모양을 그리고, **회로도 편집기**는 게이트 수준의 회로도를 그리며, **HDL 합성기**는 텍스트로 된 하드웨어 기술을 자동으로 게이트로 변환한다.

> **핵심:** 현대의 칩은 너무 커서 손으로 그릴 수 없다. 설계자는 **기능**을 HDL로 기술하고, 합성 도구가 게이트를 자동으로 만들어 낸다. 이는 컴파일러가 고급 언어 프로그램으로부터 기계어를 만들어 내는 것과 같다.

### 1.2 집적회로의 대표적인 설계 흐름

![그림 1. 집적회로의 대표적인 설계 흐름 (슬라이드 3)](../images/L05_p03.png)

*그림 1. 집적회로의 대표적인 설계 흐름 (슬라이드 3)*

설계 흐름은 위에서 아래로 진행된다.

| 단계 | 내용 |
|:-----|:-------------|
| 1. 설계 명세(Design Specification) | 요구되는 기능, 성능, 인터페이스를 문서로 정한다. |
| 2. 동작 기술(Behavioral Description) | 하드웨어의 세부 사항 없이 설계의 알고리즘을 높은 수준에서 기술한다. |
| 3. RTL 기술(HDL) | 설계를 레지스터 전송 수준, 즉 레지스터와 레지스터 사이의 데이터 전송으로 HDL로 작성한다. |
| 4. 기능 검증과 테스트(Functional Verification and Testing) | **테스트벤치**가 시뮬레이터에서 RTL 기술에 입력 패턴을 가하고, 출력을 기대 동작과 비교한다. 이 과목에서는 ModelSim이 이 역할을 한다. |
| 5. 논리 합성(Logic Synthesis) | 합성 도구가 RTL 기술을 게이트로 변환한다. |
| 6. 게이트 수준 넷리스트(Gate-Level Netlist) | 합성의 결과로, 게이트들과 이를 연결하는 선(넷)의 목록이다. |
| 7. 논리 검증과 테스트(Logical Verification and Testing) | 합성된 넷리스트를 같은 테스트벤치로 다시 시뮬레이션하므로, **합성 결과와 테스트벤치를 함께 전달**한다. |
| 8. 플로어 플래닝, 자동 배치 배선(Floor Planning, Automatic Place and Route) | 게이트를 칩 면적에 배치하고 그 사이의 배선을 연결한다. |
| 9. 물리적 레이아웃(Physical Layout) | 칩의 최종 기하학적 모양을 만든다. |
| 10. 레이아웃 검증(Layout Verification) | 레이아웃이 설계 규칙과 넷리스트에 맞는지 검사한다. |
| 11. 구현(Implementation) | 칩을 제조한다(FPGA라면 소자를 프로그래밍한다). |

- 1~5단계는 **프런트엔드**(논리 설계), 6~11단계는 **백엔드**(물리 설계)이다. 슬라이드의 빨간 선은 논리 합성 바로 뒤의 경계를 나타낸다.
- 위로 되돌아가는 화살표는 **반복**을 나타낸다. 어느 단계에서든 검증에 실패하면 설계자는 RTL 기술(또는 플로어 플래닝)로 돌아가 설계를 수정한다.

## 2. FPGA 소개

### 2.1 디지털 논리 기술

![그림 2. 디지털 논리 기술의 분류 (슬라이드 4)](../images/L05_p04.png)

*그림 2. 디지털 논리 기술의 분류 (슬라이드 4)*

| 분류 | 구성원 | 설명 |
|:---------|:--------|:------------|
| **표준 논리(Standard logic)** | TTL 74xx, CMOS 4xxx | 몇 개의 게이트나 플립플롭이 들어 있는 기능 고정형 소형 칩으로, 보드 위에서 서로 배선하여 사용한다. |
| **프로그래머블 논리(FPLDs)** | PLD, **FPGA**, CPLD | 제조 후에 사용자가 기능을 설정하는 현장 프로그래머블 논리 소자이다. |
| **ASIC** | 게이트 어레이, 스탠더드 셀 | 특정 설계 하나를 위해 제조하는 주문형 집적회로이다. |
| **풀 커스텀(Full custom)** | 마이크로프로세서와 RAM | 최고의 성능과 집적도를 위해 모든 트랜지스터를 직접 설계한다. |

슬라이드에서 강조 표시된 FPGA가 이 과목에서 사용하는 기술이다.

### 2.2 프로그래머블 논리 소자

프로그래머블 소자는 앞에서 배운 2단계 구조, 즉 곱의 항을 만드는 AND 게이트 배열과 그 뒤의 합을 만드는 OR 게이트 배열로 만들어진다. 소자들은 어느 배열을 프로그래밍할 수 있느냐에 따라 다르다.

| 소자 | 구조 | 특징 |
|:-------|:----------|:----------------|
| **PROM**(Programmable ROM) | 디코더 역할을 하는 고정 AND 배열과 프로그래밍 가능한 OR 배열 | 주로 주소 지정 메모리로 사용되며, 고정된 AND 게이트의 제약 때문에 논리 소자로는 사용하지 않는다. |
| **PLA**(Programmable Logic Array) | AND 입력과 OR 입력을 모두 프로그래밍 가능 | 가장 유연하지만 동작 속도와 집적도가 낮다. |
| **PAL**(Programmable Array Logic) | AND 입력만 프로그래밍 가능하고 OR 입력은 고정 | 이 계열에서 가장 널리 쓰이는 소자이다. |
| **CPLD**(Complex Programmable Logic Device) | PAL을 확장한 블록과 프로그래머블 레지스터(EEPROM)로 구성 | 빠른 성능이나 정확한 타이밍 예측이 필요한 곳에 적합하다. |
| **FPGA**(Field Programmable Gate Array) | **LUT**(look-up table)와 **D 플립플롭**으로 구성된 기본 셀의 집합 | 순차 논리 구현에 우수하며, 메모리, LVDS, IP 등 다양한 기능이 있어 융통성이 좋고 집적도도 높다. |

> **용어 정의:** **LUT(look-up table)** 는 k개의 주소 입력과 하나의 데이터 출력을 갖는 작은 메모리이다. 진리표의 2ᵏ개 출력값을 저장하면 k입력 LUT는 k변수의 **어떤** 부울 함수든 구현할 수 있다. **LVDS**(low-voltage differential signaling)는 입출력 핀을 위한 고속 신호 규격이고, **IP**(intellectual property) 코어는 메모리 컨트롤러나 프로세서처럼 설계에 넣어 쓸 수 있도록 미리 설계된 블록이다.

> **[컴퓨터구조]** LUT는 FPGA가 "범용"인 이유이다. FPGA는 게이트로 함수를 만드는 대신 함수의 진리표를 그대로 저장한다. 4입력 LUT는 2⁴ = 16비트, 즉 진리표의 각 행마다 한 비트를 저장한다. 따라서 FPGA를 프로그래밍한다는 것은 수천 개의 작은 진리표를 채우고 이들을 잇는 스위치를 설정하는 것이다.

### 2.3 기술 간의 트레이드오프

![그림 3. 디지털 논리 기술 사이의 트레이드오프 (슬라이드 6)](../images/L05_p06.png)

*그림 3. 디지털 논리 기술 사이의 트레이드오프 (슬라이드 6)*

- 가로축은 **엔지니어링 비용과 제품 개발에 걸리는 시간**이다.
- 세로축은 **속도, 집적도, 복잡도, 그리고 수익을 내기 위해 필요한 제품의 시장 규모**이다.
- 왼쪽 아래에서 오른쪽 위로 PLD, CPLD와 FPGA, ASIC, 풀 커스텀 VLSI 설계 순서로 놓인다. ASIC과 풀 커스텀 설계(빨간 원)는 흔히 **IC**라고 부르는, 하나의 설계를 위해 제조하는 칩이다.

트레이드오프는 분명하다. 성능과 집적도가 높을수록 개발 비용과 시간이 더 들며, 제품이 대량으로 팔릴 때만 이익이 난다. FPGA는 그 중간에 있다. 칩을 따로 제조할 필요가 없으므로 시제품 제작, 교육, 소량 생산 제품에 이상적이다.

### 2.4 FPGA의 예

## 3. HDL 기반 설계

### 3.1 HDL 설계와 컴퓨터 프로그래밍의 비교

![그림 5. HDL 설계와 컴퓨터 프로그래밍의 비교 (슬라이드 8)](../images/L05_p08.png)

*그림 5. HDL 설계와 컴퓨터 프로그래밍의 비교 (슬라이드 8)*

| 하드웨어 설계 | 컴퓨터 프로그래밍 |
|:----------------|:---------------------|
| HDL 설계(동작 기술) | 고급 언어 프로그램 |
| **합성**으로 게이트 레벨 설계(구조적 기술)로 변환 | **어셈블러** 경로를 거쳐 어셈블리 프로그램, 그리고 기계어로 변환 |
| **실리콘 컴파일러**로 바로 레이아웃으로 변환 가능 | **고급 언어 컴파일러**로 바로 기계어로 변환 |
| 최종 산출물: 레이아웃 설계 | 최종 산출물: 기계어 프로그램 |

두 흐름은 나란하다. 둘 다 사람이 높은 수준에서 작성한 기술을, (프로세서가) 실행하거나 (칩으로) 제조할 수 있는 낮은 수준의 형태로 자동 변환한다.

> **[프로그래밍언어]** 이 비유는 더 이어진다. 컴파일러의 프런트엔드가 소스 코드를 중간 표현으로 파싱하고 백엔드가 특정 프로세서용 기계어를 생성하듯이, 합성 도구는 HDL을 내부 넷리스트로 파싱한 뒤 특정 기술 라이브러리나 FPGA의 게이트에 매핑한다. 이렇게 분리되어 있기 때문에, 같은 C 프로그램을 여러 프로세서용으로 컴파일할 수 있는 것처럼 같은 HDL 소스를 여러 칩에 맞게 다시 합성할 수 있다.

### 3.2 HDL 설계 기반의 장점

**1. 설계 시간의 단축**

- 하드웨어가 만들어지기 전에 시뮬레이션으로 오류를 찾으므로, 초기 설계 과정에서 설계 오류를 수정하기 쉽다.
- 회로가 합성에 의해 생성되므로 설계 변경이 쉽다. 텍스트를 고치고 다시 합성하면 된다.

**2. 설계 품질의 향상**

- HDL은 우수하고 광범위한 하드웨어 기술 능력을 가지므로 상위 수준의 설계가 가능하다.
- 다양한 설계 기법을 검색하여 최적화된 결과에 도달할 수 있다.
- 합성 과정에서 선택적 최적화 기법(예: 속도 우선 또는 면적 우선 최적화)을 이용할 수 있다.

**3. 특정 설계 기술이나 공정과 무관한 설계**

- 특정 ASIC 제조업체나 구현 기술과 무관하게 설계할 수 있다.
- 동일한 HDL 설계를 다른 라이브러리를 이용하여 합성할 수 있다.
- (예를 들어 FPGA로) 신속한 하드웨어 **원형화(prototyping)** 가 가능하다.

**4. 낮은 설계 비용**

- 상위 레벨 설계 도구의 사용에 따라 설계 생산성이 향상된다.
- 설계 기간의 단축에 따라 설계 비용이 감소한다.
- 설계 자산(이미 작성한 모듈)의 재사용에 의해 설계 비용이 감소한다.

**5. 표준 HDL 및 사용자의 확대**

- IEEE 표준인 동시에 미국 정부의 공인 HDL이다.
- 전 세계적으로 설계 및 설계 정보 교환의 수단으로 사용이 확대되고 있다.

**6. 효율적인 설계 관리**

- HDL 언어의 **구조적 설계(structured design)** 기능을 이용하여 전체 설계를 기능별로 분할하여 설계할 수 있으며, 설계 관리와 문서화가 쉽다.

> **참고:** "미국 정부의 공인 HDL"이라는 표현은 역사적으로 또 다른 주요 HDL인 **VHDL**에 해당한다. VHDL은 미국 국방부의 VHSIC 프로그램에서 개발되었다. VHDL(IEEE 1076)과 Verilog(IEEE 1364)는 모두 IEEE 표준이다.

### 3.3 Verilog HDL의 역사

| 연도 | 사건 |
|:-----|:------|
| 1983년 | Gateway Design Automation사가 하드웨어 기술 언어인 HiLo와 C 언어의 특징을 기반으로 Verilog를 개발하였다. |
| 1991년 | Cadence Design Systems가 Open Verilog International(OVI)이라는 조직을 구성하고 Verilog HDL을 공개하였다. |
| 1993년 | IEEE Working Group이 구성되어 표준화 작업을 진행하였다. |
| 1995년 12월 | **IEEE Std. 1364-1995**로 표준화되었다. |
| 2001년 | **IEEE Std. 1364-2001**로 개정되었다. |
| 이후 | Verilog HDL의 확장 형태인 **SystemVerilog**가 개발되어 IEEE 표준화가 추진되었다. |

> **참고:** SystemVerilog는 IEEE Std. 1800-2005가 되었고, 2009년에 Verilog 표준이 이에 통합되었다(IEEE 1800-2009). SystemVerilog는 클래스와 어서션 등 주로 검증을 위한 기능을 추가하며, 합성 가능한 핵심은 여기서 배우는 Verilog 그대로이다.

## 4. 모듈

### 4.1 모듈의 계층 구조

**모듈(module)** 은 하드웨어를 구현하기 위한 기본 설계 블록이다. 설계는 세 종류의 모듈로 이루어진다.

- 설계 전체를 나타내는 **최상위 모듈(top module)**
- 다른 모듈 안에서 사용되는 **하위 모듈**
- 시뮬레이션을 위해 설계에 입력을 가하는 **테스트벤치 모듈(test bench module)**

![그림 6. 트리와 중첩 블록으로 나타낸 모듈의 계층 구조 (슬라이드 12)](../images/L05_p12.png)

*그림 6. 트리와 중첩 블록으로 나타낸 모듈의 계층 구조 (슬라이드 12)*

왼쪽 그림은 계층 구조를 트리로 나타낸다. 최상위 모듈은 모듈 1과 모듈 2를 포함하고, 모듈 2는 모듈 3, 4, 5를 포함한다. 오른쪽 그림은 같은 설계를 신호가 오가는 중첩 블록으로 나타낸다. 최상위 입력은 모듈 1과 모듈 3으로 들어가고, 모듈 3은 모듈 4와 5를 구동하며, 모듈 1, 4, 5가 최상위 출력을 만든다.

### 4.2 모듈의 구조

![그림 7. Verilog 모듈의 구조 (슬라이드 13)](../images/L05_p13.png)

*그림 7. Verilog 모듈의 구조 (슬라이드 13)*

그림은 문법의 세부 사항 두 가지를 빨간색으로 표시한다. 모듈 헤더는 **세미콜론**으로 끝나고, `endmodule`에는 **세미콜론이 없다**. 파란 상자에는 선언이, 분홍 상자에는 회로의 기술이 들어간다. 이 구조를 코드로 쓰면 다음과 같다.

```verilog
module module_name (port_list);   // 헤더는 세미콜론으로 끝난다

  // 선언
  //   port 선언       (input, output, inout)
  //   reg 선언
  //   wire 선언
  //   parameter 선언

  // 본문: 다음 중 하나 이상
  //   게이트 모델링
  //   데이터플로 모델링
  //   동작적 모델링
  //   구조적 모델링 (하위 모듈 호출)

endmodule                          // endmodule 뒤에는 세미콜론이 없다
```

모듈은 키워드 `module`, 모듈 이름, 포트 목록으로 시작하여 `endmodule`로 끝난다. 그 사이에 선언이 오고, 이어서 회로의 기능에 대한 기술이 온다.

### 4.3 기본 문법 규칙

- Verilog HDL로 표현되는 논리회로는 **`module`과 `endmodule`** 안에 있어야 한다.
- 모든 문장은 **세미콜론(;)** 으로 끝나지만, `end`로 시작하는 예약어(`endmodule`, `end`, `endcase`, `endfunction` 등)에는 **세미콜론이 없다**.
- 이름 혹은 식별자는 **소문자와 대문자를 구별**한다. `Data`와 `data`는 서로 다른 신호이다.
- Verilog HDL의 예약어는 반드시 **소문자**로 기술한다(`MODULE`이 아니라 `module`).
- 모듈 이름은 영문자와 언더바(`_`)로 시작할 수 있다.
- **주석문(comment):**
  - `/*`로 시작하여 `*/`로 끝나는 주석은 여러 행에 걸쳐 사용할 수 있다.
  - `//`로 시작하는 주석은 그 행의 끝까지만 주석이다.

### 4.4 포트

포트는 모듈과 외부를 잇는 연결이다. 각 포트는 **[포트 방향] [이름];** 의 형식으로 선언한다.

| 방향 | 의미 |
|:----------|:--------|
| `input` | 입력 포트 |
| `output` | 출력 포트 |
| `inout` | 입출력(양방향) 포트 |

```verilog
module module_name (out, ina, inb, clr);
  input  [7:0]  ina, inb;  // 8비트 입력 두 개
  input         clr;       // 1비트 입력 하나
  output [15:0] out;       // 16비트 출력 하나

  // 데이터형 선언
  // 회로 기능 구현
  // 타이밍 정보
endmodule
```

`[7:0]` 표기는 비트 번호가 7(MSB)부터 0(LSB)까지인 8비트 버스를 선언한다. 범위가 없는 포트는 1비트이다.

## 5. 데이터형

### 5.1 넷 데이터형

**넷(net)** 은 회로 기판 위의 배선처럼 하드웨어 블록 사이의 **물리적인 연결**을 나타낸다. 넷에는 저장 기능이 없으며, 값은 항상 그 넷을 구동하는 것의 값과 같다.

![그림 8. 기능 블록을 잇는 넷과 모듈 안에서 선언한 wire (슬라이드 16)](../images/L05_p16.png)

*그림 8. 기능 블록을 잇는 넷과 모듈 안에서 선언한 wire (슬라이드 16)*

위쪽 그림에서 넷은 기능 블록으로 들어가는 신호, 블록 사이의 신호, 블록에서 나오는 신호를 전달한다. 슬라이드는 자주 쓰는 넷 데이터형 네 가지 `wire`, `tri`, `supply0`, `supply1`을 나열하며, 가장 많이 쓰는 것은 `wire`이다. 아래 코드(그림의 아래쪽)는 내부 16비트 wire를 선언한다.

```verilog
module module_name (ina, inb, clr, out);
  input  [7:0]  ina, inb;
  input         clr;
  output [15:0] out;
  wire   [15:0] mult;   // 내부 16비트 넷
  // 회로 기능 구현
  // 타이밍 정보
endmodule
```

모든 넷 데이터형은 다음과 같다.

| 데이터형 | 의미 |
|:----------|:--------|
| `wire` | 논리적인 행동이나 기능 없이 단지 연결하는 데 사용한다. |
| `tri` | `wire`와 같으며, 하이 임피던스 상태가 더 있음을 나타내는 데 사용한다. |
| `supply1` | 넷을 전원(논리 1)에 연결한다. |
| `supply0` | 넷을 그라운드(논리 0)에 연결한다. |
| `tri1` | 넷을 풀업(pull up)한다(저항을 통해 전원에 연결). |
| `tri0` | 넷을 풀다운(pull down)한다(저항을 통해 그라운드에 연결). |
| `wor` | 여러 디바이스의 출력을 선으로 연결(wire)하여 "or" 기능을 하는 넷이다. |
| `trior` | wired-or와 같으나, 하이 임피던스 상태가 더 있다. |
| `wand` | 여러 디바이스의 출력을 선으로 연결(wire)하여 "and" 기능을 하는 넷이다. |
| `triand` | wired-and와 같으나, 하이 임피던스 상태가 더 있다. |
| `trireg` | 하이 임피던스 상태일 때 마지막 값을 (충전된 커패시터처럼) 유지하는 저장형 넷이다. |

### 5.2 변수 데이터형

**변수(variable)** 는 **데이터를 저장할 수 있는** 연결이다.

- **`reg`:** `always` 문(또는 `initial` 문)에 의해 값이 만들어지는 신호이다.
- **`integer`:** 부호 있는 32비트 변수이다.

```verilog
module module_name (ina, inb, clr, out);
  input  [7:0]  ina, inb;
  input         clr;
  output [15:0] out;
  reg    [15:0] out;    // out은 always 블록에서 대입되므로 reg로 선언한다
  // 회로 기능 구현
  // 타이밍 정보
endmodule
```

> **핵심:** `reg`가 반드시 하드웨어 레지스터(플립플롭)가 되는 것은 **아니다**. 이 이름은 절차적 코드 안에서 대입과 대입 사이에 값을 유지하는 신호라는 뜻일 뿐이다. 조합회로용 `always` 블록에서 대입한 `reg`는 평범한 게이트로 합성되고, 클록 에지에서 대입한 `reg`는 플립플롭으로 합성된다.

### 5.3 선언 형식과 벡터

신호는 **[신호 Type] [msb:lsb] [이름 리스트];** 의 형식으로 선언한다.

| 선언 | 의미 |
|:------------|:--------|
| `reg` | 소프트웨어의 변수와 유사하게 값을 기억하는 1비트 신호이다. |
| `wire` | 값 전달 위주의 전기적인 연결선 역할을 하는 1비트 신호이다. |
| `reg [msb:lsb]` | 다중 비트(vectored) `reg` 신호이다. |
| `wire [msb:lsb]` | 다중 비트(vectored) `wire` 신호이다. |
| `reg signed [msb:lsb]` | 부호 있는 수(2의 보수)로 해석하는 다중 비트(vectored) `reg` 신호이다. |
| `wire signed [msb:lsb]` | 부호 있는 수로 해석하는 다중 비트(vectored) `wire` 신호이다. |

벡터의 개별 비트와 범위를 선택할 수 있다. `wire [7:0] d;`에서 `d[0]`은 LSB, `d[7]`은 MSB, `d[3:0]`은 하위 4비트이다.

### 5.4 논리값

Verilog 신호는 네 가지 값을 가질 수 있다.

| 값 | 의미 |
|:-----:|:--------|
| `1` | 논리값 1, 참(true) |
| `0` | 논리값 0, 거짓(false) |
| `Z` | 하이 임피던스: 아무것도 신호를 구동하지 않는 상태(개방 회로) |
| `X` | 알 수 없는 값(unknown): 시뮬레이터가 0인지 1인지 결정할 수 없는 상태 |

`X`는 보통 시뮬레이션 초기에 `reg`가 아직 대입되지 않았을 때, 또는 두 구동원이 서로 다른 값으로 한 넷을 구동할 때 나타난다. `Z`는 트라이스테이트 버퍼처럼 모든 구동원이 비활성화된 넷에 나타난다.

### 5.5 수 상수

벡터 상수는 **[신호의 길이]'[진수][신호의 값]** 의 형식으로 쓴다.

| 진수 코드 | 의미 | 부호 있는 진수 코드 | 의미 |
|:---------:|:--------|:----------------:|:--------|
| `h` | 16진수 | `sh` | 부호 있는 16진수 |
| `o` | 8진수 | `so` | 부호 있는 8진수 |
| `d` | 10진수 | `sd` | 부호 있는 10진수 |
| `b` | 2진수 | `sb` | 부호 있는 2진수 |

**사용 예:**

| 상수 | 의미 |
|:---------|:--------|
| `0` | 10진수 0 |
| `8` | 10진수 8 |
| `4'b1010` | 4비트 2진수 1010 |
| `'ha` | 16진수 a(길이 지정 없음) |

- 길이는 자릿수가 아니라 **비트** 수이다. `8'hFF`는 8비트 값이고, `4'd9`는 10진수 9를 4비트에 저장한 것이다.
- 길이와 진수가 없는 수(예: `8`)는 최소 32비트의 10진수이다.
- 가독성을 위해 언더바를 넣을 수 있으며, 언더바는 무시된다: `8'b1010_0011`

### 5.6 파라미터

**파라미터(parameter)** 는 이름 붙은 상수를 정의한다: **parameter [범위] 이름 = 식;**. 파라미터를 사용하면 하나의 모듈을 크기나 지연을 바꾸어 재사용할 수 있다.

```verilog
module modXnor (y_out, a, b);
  parameter size = 8, delay = 15;     // 기본값
  output [size-1:0] y_out;
  input  [size-1:0] a, b;
  wire   [size-1:0] #delay y_out = a ~^ b;  // "delay" 시간 단위 뒤에 비트 단위 XNOR
endmodule

module Param;
  wire [7:0] y1_out;
  wire [3:0] y2_out;
  reg  [7:0] b1, c1;
  reg  [3:0] b2, c2;

  modXnor        G1 (y1_out, b1, c1);   // 기본값 사용: size = 8, delay = 15
  modXnor #(4, 5) G2 (y2_out, b2, c2);  // 재정의: size = 4, delay = 5
endmodule
```

**행별 설명:**

- `modXnor`는 `size`비트 입력 두 개의 비트 단위 XNOR(`~^`)를 계산한다. 선언 `wire [size-1:0] #delay y_out = a ~^ b;`는 출력을 넷으로 선언하면서 `delay` 시간 단위의 지연을 두고 연속적으로 대입한다.
- `Param`에서 인스턴스 `G1`은 기본 파라미터를 사용하므로 지연이 15인 8비트 XNOR이다.
- 인스턴스 `G2`는 `#(4, 5)`로 작성되어, 파라미터를 선언된 순서대로 `size = 4`, `delay = 5`로 재정의한다. 따라서 같은 모듈이 지연이 5인 4비트 XNOR가 되며, 포트 폭도 4비트 신호 `y2_out`, `b2`, `c2`와 맞는다.

## 6. 인스턴스

### 6.1 포트 이름에 의한 연결과 순서에 의한 연결

다른 모듈이나 게이트 프리미티브(gate primitive)를 호출해서 사용하는 것을 **인스턴스화(instantiation)** 라고 하며, 각각의 사용을 **인스턴스(instance)** 라고 부른다. 인스턴스의 포트를 연결하는 방법은 두 가지이다.

- **포트 이름에 의한 연결**(named mapping): `.포트이름(신호)` 형태로 쓴다.
  - 사용하는 포트 이름은 하위 계층 모듈의 포트 이름과 반드시 일치해야 한다.
  - 인스턴스 이름은 사용자가 임의로 부여한다(예: ADD0, ..., ADD3).
- **포트 목록 순서에 의한 연결**(positional mapping): 하위 모듈의 선언에 기술된 포트 순서대로 신호를 나열한다.

**예제: 반가산기 두 개로 만든 전가산기.**

```verilog
module full_adder(fco, fsum, cin, a, b);
  output fco, fsum;
  input  cin, a, b;

  wire c1, s1, c2;                    // 인스턴스 사이의 내부 넷

  half_adder u1 (c1, s1, a, b);                          // 순서에 의한 연결
  half_adder u2 (.a(s1), .b(cin), .sum(fsum), .co(c2));  // 이름에 의한 연결
  or         u3 (fco, c1, c2);                           // 게이트 프리미티브 인스턴스
endmodule
```

하위 모듈 `half_adder`는 슬라이드에 나오지 않는다. 인스턴스 `u1`이 동작하려면 포트가 (자리올림, 합, a, b) 순서로 선언되어 있어야 한다. 이에 맞는 정의는 다음과 같다.

```verilog
module half_adder(co, sum, a, b);
  output co, sum;
  input  a, b;
  assign co  = a & b;   // 자리올림 = AND
  assign sum = a ^ b;   // 합 = XOR
endmodule
```

**전가산기의 동작:** `u1`은 a와 b를 더하여 부분합 s1과 자리올림 c1을 만든다. `u2`는 s1과 입력 자리올림 cin을 더하여 최종 합 fsum과 두 번째 자리올림 c2를 만든다. 두 반가산기 중 어느 하나라도 자리올림을 만들면 출력 자리올림 fco가 1이므로, `u3`가 c1과 c2를 OR한다.

> **시험 팁:** 이름에 의한 연결이 순서에 의한 연결보다 안전하다. 하위 모듈의 포트 순서가 바뀌어도 연결이 올바르게 유지되고, 포트 이름이 빠지거나 틀리면 잘못된 연결이 조용히 만들어지는 대신 오류가 발생하기 때문이다.

### 6.2 예제: 전가산기로 만든 4비트 가산기

인스턴스는 이미 만들어져 있는 모듈을 불러와서 만든 블록이다. 1비트 전가산기(FA)의 인스턴스 네 개로 4비트 가산기를 만든다.

![그림 9. 1비트 전가산기 모듈과 이를 네 번 인스턴스화하여 만든 4비트 가산기 (슬라이드 25)](../images/L05_p25.png)

*그림 9. 1비트 전가산기 모듈과 이를 네 번 인스턴스화하여 만든 4비트 가산기 (슬라이드 25)*

- 1비트 FA 모듈의 입력은 A, B, C_in이고 출력은 S와 C_out이다.
- 4비트 가산기에서 FA0은 A[0]과 B[0]을 더하고, 그 출력 자리올림이 FA1의 입력 자리올림으로 들어가며, 이렇게 FA3까지 이어진다. FA3의 출력 자리올림이 최종 자리올림이다. 이러한 연결을 **리플 캐리 가산기(ripple-carry adder)** 라고 한다.

```verilog
module FA4(s, c_out, a, b, c_in);   // 완성된 4비트 전가산기
  output [3:0] s;
  output       c_out;
  input  [3:0] a, b;
  input        c_in;

  wire c1, c2, c3;                  // 단 사이의 자리올림

  FA fa0(s[0], c1,    a[0], b[0], c_in);
  FA fa1(s[1], c2,    a[1], b[1], c1);
  FA fa2(s[2], c3,    a[2], b[2], c2);
  FA fa3(s[3], c_out, a[3], b[3], c3);
endmodule
```

> **참고:** 슬라이드에는 인스턴스 `fa2`가 `FA fa2(s[2], c2, a[2], b[2], c2);`로 쓰여 있다. 이렇게 하면 2단의 출력 자리올림이 자기 입력 자리올림과 같은 넷 `c2`에 연결되고 `c3`는 구동되지 않는다. 위와 같이 `fa2`의 올바른 출력 자리올림은 `c3`이다. 여기서 `FA`의 포트 순서는 (합, 출력 자리올림, a, b, 입력 자리올림)이다.

> **[컴퓨터구조]** 리플 캐리 가산기에서는 각 단이 이전 단의 자리올림을 기다려야 하므로, 지연이 비트 수에 비례하여 늘어난다. 32비트나 64비트 ALU에서는 너무 느리므로, 프로세서는 "생성(generate)"(aᵢbᵢ) 신호와 "전파(propagate)"(aᵢ ⊕ bᵢ) 신호로부터 모든 자리올림을 병렬로 계산하는 **캐리 룩어헤드 가산기(carry-lookahead adder)** 를 사용한다.

## 7. 추상화 수준과 모델링 방식

Verilog 모듈은 여러 추상화 수준에서 기술할 수 있다.

| 수준 | 추상도 | 논리 합성 | 의미 |
|:------|:-----------:|:---------------:|:--------|
| 아키텍처 수준(Architecture level) | 고 | 불가 | 파이프라인이나 캐시 등 시스템 내의 기능을 표현한 수준이다. |
| 동작 수준(Behavior level) | ↑ | 부분적 | 회로의 동작, 움직임을 표현한 수준이며, 블록 개념이 없다. |
| 레지스터 전송 수준(RTL) | | 가능 | 레지스터 간의 동작을 표현한 수준이며, 블록 개념이 있다. |
| 게이트 수준(Gate level) | ↓ | 가능 | 플립플롭이나 게이트 회로로 표현한 수준이다. |
| 스위치 수준(Switch level) | 저 | 불가 | PMOS, NMOS 등의 트랜지스터 수준이다. |

> **참고:** 슬라이드는 "register"를 "Resister"로, "transistor"를 "Transister"로 표기하는데, 둘 다 오타이다.

- "부분적"으로 합성 가능하다는 것은 동작적 구문 중 일부(예: 명시적 지연이 없는 `always` 블록)만 하드웨어로 바꿀 수 있다는 뜻이다. `#10` 같은 지연과 `initial` 블록은 시뮬레이션 전용이다.

실제로 사용하는 모델링 방식은 다음과 같이 묶인다.

| 묶음 | 모델링 방식 |
|:------|:---------------|
| **구조적 모델링(Structural modeling)** | 게이트 수준 모델링 |
| **기능적 모델링(Functional modeling)** | 레지스터 전송 수준(RTL) 모델링, 동작적 모델링 |

## 8. 게이트 수준 모델링

게이트 수준 모델링은 논리 게이트(AND, OR, NOT, NAND 등)를 사용하여 하드웨어를 구현한다. Verilog는 게이트를 내장된 **게이트 원시 함수(gate primitive)** 로 제공한다. 모든 원시 함수에서 **출력이 먼저** 오고 그 뒤에 입력이 온다.

```verilog
and and_test(out, in0, in1);   // out = in0 AND in1
or  or_test (x, a, b);         // x   = a OR b
```

| 원시 함수 | 기능 | 비고 |
|:----------|:---------|:--------|
| `and` | 논리 AND | |
| `or` | 논리 OR | |
| `nand` | 논리 NAND | |
| `nor` | 논리 NOR | |
| `xor` | 논리 배타적 OR | |
| `xnor` | 논리 배타적 NOR | |
| `buf` | 버퍼 | |
| `not` | 인버터 | |
| `bufif1` | 트라이스테이트 버퍼(액티브 하이 인에이블) | 세 개의 포트를 사용하며, 첫 번째는 출력, 두 번째는 입력, 세 번째는 제어 신호이다. |
| `bufif0` | 트라이스테이트 버퍼(액티브 로우 인에이블) | 위와 같음 |
| `notif1` | 반전 트라이스테이트 버퍼(액티브 하이 인에이블) | 위와 같음 |
| `notif0` | 반전 트라이스테이트 버퍼(액티브 로우 인에이블) | 위와 같음 |

- 원시 함수 `and`, `or`, `nand`, `nor`, `xor`, `xnor`는 입력을 몇 개든 받을 수 있다. `and g1(y, a, b, c);`는 3입력 AND 게이트이다.
- **트라이스테이트 버퍼(tri-state buffer)** 는 인에이블되면 입력을 출력으로 전달하고, 디스에이블되면 출력을 하이 임피던스(`Z`)로 만든다. "액티브 하이 인에이블"은 버퍼를 인에이블하려면 제어 신호가 1이어야 한다는 뜻이고, "액티브 로우"는 0이어야 한다는 뜻이다.

## 9. 레지스터 전송 수준(데이터플로) 모델링

- RTL 모델링은 복잡한 회로를 설계하기 위한 모델링 방법이다.
- **데이터플로 모델링(data-flow modeling)** 이라고도 한다.
- 상세한 블록 다이어그램 수준의 설계를 필요로 한다.
- 회로의 구성 요소인 블록을 설계하고, 그것들 사이의 연결 및 데이터의 전송 상태를 표현한다.
- **`assign`** 문(연속 대입문)으로 신호를 연결한다.

**예제: 반가산기.**

```verilog
module HADD(C, S, in1, in2);
  input  in1, in2;         // 입력 포트
  output C, S;             // 출력 포트

  assign C = in1 & in2;    // in1과 in2를 AND하여 C에 저장
  assign S = in1 ^ in2;    // in1과 in2를 XOR하여 S에 저장
endmodule
```

**`assign` 문의 사용 규칙:**

- **왼쪽**에는 출력하는 벡터나 결합 벡터(넷)가 온다.
- **오른쪽**에는 레지스터, 넷, 함수 호출(function call) 등이 온다.
- **오른쪽 값이 변하면 왼쪽 값도 바로 변한다.** `assign`은 한 번 실행되는 것이 아니라 영구적인 연결을 기술한다.

```verilog
assign out = in1 & in2;
assign addr[15:0] = a[15:0] ^ b[15:0];
assign {c_out, sum[3:0]} = a[3:0] + b[3:0] + c_in;
assign out[4:0] = {c_out, sum[3:0]};
```

- 세 번째 행은 4비트 수 두 개와 자리올림을 더한다. 결과에는 5비트가 필요하므로 결합 `{c_out, sum[3:0]}`에 대입한다. MSB는 `c_out`으로, 하위 4비트는 `sum`으로 간다.
- 네 번째 행은 그 반대로, `c_out`과 `sum`을 하나의 5비트 출력으로 합친다.

**예제: `assign`을 사용한 4비트 가산기.**

```verilog
module ADD_4bit(s, c, in1, in2, c_in);  // 4비트 전가산기
  output [3:0] s;
  output       c;
  input  [3:0] in1, in2;
  input        c_in;

  assign {c, s} = in1 + in2 + c_in;
endmodule
```

6.2절의 구조적 `FA4`와 비교하면, 이 버전은 **기능**(덧셈)을 한 줄로 기술하고 게이트 구조는 합성 도구에 맡긴다.

> **참고:** 슬라이드에는 `assign` 행 끝에 세미콜론이 없다. 위와 같이 세미콜론이 필요하며, 없으면 컴파일러가 문법 오류를 보고한다.

## 10. 동작적 모델링

### 10.1 개요

- 동작적 모델링은 Verilog HDL에서 **가장 높은 추상화 단계**의 하드웨어 모델링 기법이다.
- 논리 게이트나 데이터 흐름을 고려할 필요 없이 하드웨어 동작의 **알고리즘**을 모델링한다.
- 주요 구문은 `initial`, `always @`, `if-else`, `case`, 반복문이다.

```verilog
module ...
  always @* begin
    if (sela)
      q = a;
    else if (selb)
      q = b;
    else
      q = c;
  end
endmodule
```

이 블록은 우선순위가 있는 선택기를 기술한다. `sela`가 1이면 q는 a를 받고, 그렇지 않고 `selb`가 1이면 q는 b를 받으며, 둘 다 아니면 q는 c를 받는다. 이벤트 목록 `@*`는 "블록 안에서 읽는 신호 중 어느 것이든 변할 때마다"라는 뜻으로, 조합 논리에 알맞은 감지 목록이다.

### 10.2 initial 문

- Verilog HDL은 **모든 구문이 병렬적으로 실행된다**.
- `initial` 구문은 시뮬레이션 시작과 함께 시작하며, 시뮬레이션 동안 **딱 한 번만 수행된다**.
- 각 블록은 독립적으로 실행되며, 모든 `initial` 블록은 동시에(시간 0에) 시작한다.
- 초기값 설정 시와 **테스트벤치**에서 사용된다.
- 여러 개의 동작을 실행한다면 시작과 끝에 **`begin`과 `end`** 가 있어야 한다.
- `initial`에서 할당되는 신호들은 **`reg`** 로 선언되어야 한다.

**예제:**

```verilog
`timescale 1 ns / 1 ps
module test1;
  reg x, y, a, b, m;

  initial m = 1'b0;          // 0 ns에 초기화

  initial begin
    #5  a = 1'b1;            // 5 ns
    #25 b = 1'b0;            // 30 ns
  end

  initial begin
    #10 x = 1'b0;            // 10 ns
    #25 y = 1'b1;            // 35 ns
  end

  initial #50 $finish;       // 50 ns에 시뮬레이션 종료
endmodule
```

**행별 설명:**

- `` `timescale 1 ns / 1 ps ``는 시간 단위를 1 ns로(따라서 `#5`는 5 ns), 시뮬레이션 정밀도를 1 ps로 설정한다.
- `#n`은 지연으로, n 시간 단위를 기다린 뒤 문장을 실행한다. 하나의 `begin ... end` 블록 안에서 지연은 **누적된다**. 두 번째 블록에서 a는 5 ns에, b는 5 + 25 = 30 ns에 설정된다.
- 네 개의 `initial` 블록은 각자의 시간선을 가지고 **동시에** 실행된다. 따라서 두 번째 블록과 관계없이 x는 10 ns에, y는 10 + 25 = 35 ns에 설정된다.
- `$finish`는 50 ns에 시뮬레이션을 멈춘다.

![그림 10. initial 문 예제의 파형 (슬라이드 38)](../images/L05_p38.png)

*그림 10. initial 문 예제의 파형 (슬라이드 38)*

파형 창에는 신호 x, y, a, b, m이 나열된다. 각 신호는 처음 대입되기 전까지 알 수 없는 값(`X`)이며, 대입된 뒤에는 그 값을 갖는다. m은 처음부터 0이고, a는 5 ns에 1이 되며, x는 10 ns에 0이 되고, b는 30 ns에 0이 되며, y는 35 ns에 1이 되고, 시뮬레이션은 50 ns 표시에서 멈춘다.

> **[프로그래밍언어]** 각 `initial` 블록이나 `always` 블록은 병행 프로그램의 독립적인 **프로세스**(또는 스레드)처럼 동작하며, 시뮬레이터는 시뮬레이션 시간에 따라 이들을 번갈아 실행한다. 다만 운영체제의 스레드와 달리, 시간에 대한 순서는 결정적이다. 서로 다른 시간에 예약된 문장은 항상 시간 순서대로 실행된다. 그러나 서로 다른 블록에서 **같은** 시간에 예약된 문장들은 어떤 순서로든 실행될 수 있으며, 이것이 논블로킹 대입(10.5절)이 피하고자 하는 경쟁 조건의 원인이다.

### 10.3 always 문

**구문 형식:**

```verilog
always @ (이벤트)
begin
  // 하드웨어 동작에 대한 코드
end
```

**`always` 문의 특징:**

- `always` 문 블록에는 언제 실행할지를 정하는 **이벤트**(또는 지연)가 반드시 있어야 한다.
- `always` 문 내에서 할당되는 신호들은 **`reg`** 로 선언되어야 한다.

**조합회로에서 `always` 문을 사용할 때 주의할 점(슬라이드 내용):**

- 반드시 `@(event signal)`이 존재해야 한다.
- 조합회로에 공급되는 모든 신호들은 `@(event signal)`에 존재해야 한다.
- `always` 블록에서 할당되는 신호들은 반드시 `reg` 또는 `integer`로 선언한다(`always`의 동작은 일종의 레지스터로 생각한다).
- `always` 문 내에서는 논블로킹 대입문(`<=`)을 사용한다.

**순차회로에서 `always` 문을 사용할 때 주의할 점:**

- `@(event signal)` 없이 사용할 경우 블록 내에 이벤트를 일으키는 식(예: 지연 `#10`)이 포함되어야 한다. 그렇지 않으면 블록이 시간 0에서 영원히 반복된다.

한 모듈 안에서 **`always` 문을 여러 개** 사용할 수도 있으며, 모두 동시에 실행된다.

> **참고:** 슬라이드의 조합회로 지침은 논블로킹 대입을 권하지만, 뒤의 슬라이드(10.5절)는 표준 관례인 규칙, 즉 **조합 논리에는 블로킹 대입(`=`)**, **순차 논리에는 논블로킹 대입(`<=`)** 을 제시한다. 시험에서는 교수자의 설명을 따르되, 실무에서는 표준 규칙을 따라야 시뮬레이션과 합성 결과의 불일치를 피할 수 있다. 조합 논리의 **모든 입력**을 이벤트 목록에 넣어야 한다는 요구는 매우 중요하다. 신호가 하나라도 빠지면 시뮬레이션이 래치처럼 동작하여 합성된 하드웨어와 달라진다. `@*`라고 쓰면 모든 입력이 자동으로 포함된다.

### 10.4 always 블록의 예

**예제 1: `always`를 사용한 4비트 가산기.**

```verilog
module ADD_4bit(out, in1, in2);
  input  [3:0] in1, in2;   // 입력 포트
  output [4:0] out;        // 출력 포트

  reg    [4:0] out;        // always 블록에서 변경된 값을 할당

  always @(in1, in2)
  begin
    out = in1 + in2;
  end
endmodule
```

![그림 11. 4비트 가산기의 시뮬레이션 파형 (슬라이드 41)](../images/L05_p41.png)

*그림 11. 4비트 가산기의 시뮬레이션 파형 (슬라이드 41)*

이 블록은 `in1`이나 `in2`가 변할 때마다 실행된다. 파형은 연속된 네 구간을 보여 준다.

| in1 | in2 | out = in1 + in2 |
|:---:|:---:|:---------------:|
| 1010 (10) | 0000 (0) | 01010 (10) |
| 1010 (10) | 1100 (12) | 10110 (22) |
| 0000 (0) | 1100 (12) | 01100 (12) |
| 0000 (0) | 0000 (0) | 00000 (0) |

출력을 5비트로 하여 (10 + 12 = 22처럼) 덧셈의 자리올림을 잃지 않게 한다.

**예제 2: 클록 생성기.**

- `always` 문은 블록 내의 문장을 **연속되게(영원히)** 수행한다.
- 동작적 모델링(행위 수준 모델링) 시 조건이 없는 `always` 블록은 **무한 루프**이다.

```verilog
module clock_test;
  reg clock;

  initial clock = 1'b0;          // 클록은 0에서 시작한다
  always #10 clock = ~clock;     // 10 시간 단위마다 클록을 반전한다
  initial #50 $finish;           // 50에서 시뮬레이션을 멈춘다
endmodule
```

![그림 12. 클록 생성기의 파형 (슬라이드 42)](../images/L05_p42.png)

*그림 12. 클록 생성기의 파형 (슬라이드 42)*

`always` 블록은 10 시간 단위를 기다린 뒤 클록을 반전하고, 이를 반복한다. 따라서 클록은 0~10에서 0, 10~20에서 1, 20~30에서 0, 30~40에서 1, 40~50에서 0이며, 50에서 시뮬레이션이 멈춘다. 즉, 주기가 20 시간 단위인 구형파이다. 이것이 테스트벤치에서 클록을 만드는 표준 방법이다.

**예제 3: 에지 이벤트.** `always` 블록의 이벤트 조건은 대부분 클록 에지이다.

```verilog
always @(posedge clock)   // clock의 상승 에지(rising edge)에서만 블록이 실행된다
always @(negedge clock)   // clock의 하강 에지(falling edge)에서만 블록이 실행된다
// 괄호 안의 이벤트에 대해 동작한다
```

- **상승 에지**(`posedge`)는 0에서 1로의 변화이고, **하강 에지**(`negedge`)는 1에서 0으로의 변화이다.
- `always @(posedge clock)` 블록은 **에지 트리거 플립플롭**을 기술한다. 그 안에서 대입되는 신호는 클록의 상승 에지에서만 바뀐다.

### 10.5 블로킹 대입과 논블로킹 대입

`initial` 블록과 `always` 블록 안에는 두 종류의 **절차적 대입(procedural assignment)** 이 있다.

| 대입 | 연산자 | 블록 안에서의 실행 |
|:-----------|:--------:|:-------------------------|
| **블로킹(Blocking)** | `=` | 순차적: 각 대입이 끝난 뒤에 다음 문장이 시작된다. |
| **논블로킹(Nonblocking)** | `<=` | 병렬적: 모든 오른쪽 식을 먼저 계산한 뒤, 왼쪽을 나중에 한꺼번에 갱신한다. |

**지연이 있는 예제:**

```verilog
module blocking;                  module nonblocking;
  reg x, y, z;                      reg x, y, z;
  initial begin                     initial begin
    x = 1'b0; y = 1'b0; z = 1'b0;     x = 1'b0; y = 1'b0; z = 1'b0;
    x = #10 1'b1;                     x <= #10 1'b1;
    y = #15 1'b1;                     y <= #15 1'b1;
    z = 1'b1;                         z <= 1'b1;
  end                               end
  initial #50 $finish;              initial #50 $finish;
endmodule                         endmodule
```

여기서 `x = #10 1'b1`은 **대입 내 지연(intra-assignment delay)** 이다. 오른쪽 식을 계산하고, 10 시간 단위 뒤에 대입한다.

| 신호 | 블로킹 버전 | 논블로킹 버전 |
|:------:|:-----------------|:--------------------|
| x | 시간 10에 1이 됨 | 시간 10에 1이 됨 |
| y | 시간 25에 1이 됨(x의 대입이 끝나기를 기다린 뒤 15를 더 기다림) | 시간 15에 1이 됨(시간 0에 독립적으로 예약됨) |
| z | 시간 25에 1이 됨(y의 대입이 끝난 뒤) | 시간 0에 1이 됨(지연 없음) |

블로킹 버전에서는 각 문장이 끝날 때까지 다음 문장을 **막으므로(block)** 지연이 누적된다. 논블로킹 버전에서는 세 대입이 모두 시간 0에 예약되어 각자 독립적으로 완료된다.

**블로킹 대입(`=`) 자세히 보기.**

- "하나의 대입이 끝나고 나서, 다음 대입을 한다."
- 즉, 기술된 순서에 따라서 회로 동작이 다르기 때문에 **순차회로에 부적합**하다.

| | [1] | [2] |
|:-|:----|:----|
| 코드 | `always @(posedge CLK) begin C = B; B = A; A = D; end` | `always @(posedge CLK) begin A = D; C = B; B = A; end` |
| 처리 전의 초기 값 | A = 5, B = 3, C = 10, D = 2 | A = 5, B = 3, C = 10, D = 2 |
| 처리 결과 | **A = 2, B = 5, C = 3, D = 2** | **A = 2, B = 2, C = 3, D = 2** |
| 비고 | | A = D의 처리 결과가 B = A에 영향 |

[1]을 추적하면 C = B로 C = 3, B = A로 B = 5, A = D로 A = 2이다. [2]를 추적하면 A = D로 A = 2, C = B로 C = 3이 되고, B = A는 **새로운** A를 읽어 B = 2가 된다. 문장의 순서만 바꾸었는데 회로가 달라졌다.

**논블로킹 대입(`<=`) 자세히 보기.**

- `always` 문 블록 내의 대입식에서 오른쪽 처리가 완전히 끝나고 나면, 일제히 왼쪽에 대입한다.
- 즉, 기술된 순서와 무관하게 회로가 동작하므로 **순차회로에 적합**하다.

| | [1] | [2] |
|:-|:----|:----|
| 코드 | `always @(posedge CLK) begin C <= B; B <= A; A <= D; end` | `always @(posedge CLK) begin A <= D; C <= B; B <= A; end` |
| 처리 전의 초기 값 | A = 5, B = 3, C = 10, D = 2 | A = 5, B = 3, C = 10, D = 2 |
| 처리 결과 | **A = 2, B = 5, C = 3, D = 2** | **A = 2, B = 5, C = 3, D = 2** |
| 비고 | 오른쪽 B, A, D 값이 처리된 후, 일제히 왼쪽에 대입 | 오른쪽 D, B, A 값이 처리된 후, 일제히 왼쪽에 대입 |

어떤 레지스터도 바뀌기 전에 모든 오른쪽 식이 **이전** 값(B = 3, A = 5, D = 2)을 읽으므로, 두 순서의 결과가 같다. 이것은 실제 플립플롭의 동작과 정확히 같다. 모든 플립플롭은 같은 클록 에지에서 입력을 샘플링한다.

> **참고:** 슬라이드는 A, B, C, D를 `wire [3:0]`로 선언한다. `always` 블록 안에서 대입되는 신호는 `reg`로 선언해야 하므로, 실제 코드에서는 `reg [3:0] A, B, C, D;`이어야 한다.

![그림 13. 블로킹 대입과 논블로킹 대입의 차이 (슬라이드 47)](../images/L05_p47.png)

*그림 13. 블로킹 대입과 논블로킹 대입의 차이 (슬라이드 47)*

- **조합회로:** 블로킹(`=`)
- **순차회로:** 논블로킹(`<=`)
- 그림에서 블로킹 쌍 `A = B; C = A;`는 한 줄씩(지그재그로) 읽힌다. C는 A의 **새** 값, 즉 B를 받는다. 기술 순서가 동작에 영향을 준다.
- 논블로킹 쌍 `A <= B; C <= A;`에서는 두 오른쪽 식을 먼저 읽는다(대각선). C는 A의 **이전** 값을 받는다. 기술 순서는 동작과 무관하다.

> **핵심:** 논블로킹 대입으로 쓴 `A <= B; C <= A;`는 **직렬로 연결된 두 플립플롭**(시프트 레지스터)을 기술한다. 클록 에지마다 값이 한 단씩 이동한다. 같은 줄을 블로킹 대입으로 쓰면 C가 곧바로 B와 같아져서 두 단이 하나로 합쳐진다.

> **[프로그래밍언어]** 논블로킹 대입은 **2단계(two-phase)** 의미를 갖는다. 이전 상태의 스냅숏으로부터 모든 새 값을 계산한 뒤 이를 한꺼번에 반영하는 것과 비슷하다. 일반 프로그래밍 언어에는 블로킹 형태만 있으므로 C에서 두 값을 맞바꾸려면 임시 변수가 필요하지만, Verilog에서는 `a <= b; b <= a;`로 두 레지스터를 올바르게 맞바꿀 수 있다.

### 10.6 if 문

**1. 조건에 따라 처리할 구문이 하나인 경우:**

```verilog
// 조건이 1개
if (조건) true_statement;

// 조건이 2개
if (조건) true_statement;
else      false_statement;

// 조건이 3개 이상
if (조건)      true_statement;
else if (조건) true_statement;
else if (조건) true_statement;
else           default_statement;
```

**2. 조건에 따라 처리할 구문이 다수 개인 경우:** 구문들을 `begin`과 `end`로 감싸야 한다.

```verilog
if (조건식)
  begin
    true_statement1;
    true_statement2;
  end
else
  begin
    false_statement;
  end
```

`if-else if` 연쇄는 조건을 **차례로** 검사하므로, 첫 번째 조건의 우선순위가 가장 높다.

### 10.7 예제: 2, 3, 4, 7, 8, 10, 11을 순환하는 카운터

```verilog
module counter_test(clock, reset, b);       // 이벤트에 의한 카운터
  input        clock, reset;
  output [3:0] b;
  reg    [3:0] b;

  always @(posedge clock or negedge reset)
    begin
      if (!reset)
        b = 2;                              // reset = 0이면 b = 2
      else
        begin
          if (b == 4)       b = 7;
          else if (b == 8)  b = 10;
          else if (b == 11) b = 2;
          else              b = b + 1;
        end
    end
endmodule
```

**동작 방법:**

- 블록은 `clock`의 모든 상승 에지와 `reset`의 모든 하강 에지에서 실행된다.
- `reset`이 0이면 카운터를 강제로 2로 만든다.
- 그렇지 않으면 클록의 상승 에지마다 카운터는 보통 1을 더하지만, 4에서 7로, 8에서 10으로, 11에서 다시 2로 건너뛴다.

| 클록 에지 | 이전 b | 이후 b |
|:----------:|:--------:|:-------:|
| 1 | 2 | 3 |
| 2 | 3 | 4 |
| 3 | 4 | 7 |
| 4 | 7 | 8 |
| 5 | 8 | 10 |
| 6 | 10 | 11 |
| 7 | 11 | 2 |

> **참고:** 슬라이드는 이벤트 행에 "동기식"이라는 주석을 달았지만, 이벤트 목록에 `negedge reset`이 있으므로 카운터는 클록 에지를 기다리지 않고 `reset`이 떨어지는 즉시 리셋된다. 이는 **비동기식** 액티브 로우 리셋이다. 또한 순차회로이므로 표준 관례대로라면 대입을 논블로킹(`b <= b + 1;`)으로 써야 한다. 블록에서 대입하는 레지스터가 하나뿐이므로 이 예제에서는 두 형태의 시뮬레이션 결과가 같다.

### 10.8 case 문

- 조건이 여러 개일 때 `if` 문보다 간단히 사용할 수 있다.
- 조건의 참, 거짓이 아니라 논리식의 **값**에 따라서 실행할 문장을 선택한다.

```verilog
case (수식)
  조건1   : statement1;
  조건2   : statement2;
  조건3   : statement3;
  default : statement4;
endcase
```

조건에 따른 실행문이 2개 이상일 경우 `begin`과 `end`로 감싼다.

```verilog
case (수식)
  조건1 :
    begin
      statement1;
      statement2;
    end
  조건2 :
    begin
      statement1;
      statement2;
    end
  default : statement1;
endcase
```

`default` 분기는 다른 어떤 값과도 일치하지 않을 때 실행된다. 조합 논리에서는 모든 경우에 출력이 대입되도록 `default`를 항상 두어야 한다(또는 모든 값을 다루어야 한다).

### 10.9 case 문과 if 문의 비교: 4x1 멀티플렉서

4x1 멀티플렉서는 2비트 선택 신호에 따라 4비트 입력 네 개 중 하나를 선택한다.

**`if`로 설계:**

```verilog
module if_mux(a, b, c, d, x, sel);
  input  [3:0] a, b, c, d;
  input  [1:0] sel;
  output [3:0] x;
  reg    [3:0] x;

  always @(a or b or c or d or sel)
    begin
      if (sel == 2'b00)      x = a;
      else if (sel == 2'b01) x = b;
      else if (sel == 2'b10) x = c;
      else if (sel == 2'b11) x = d;
    end
endmodule
```

**`case`로 설계:**

```verilog
module case_mux(a, b, c, d, x, sel);
  input  [3:0] a, b, c, d;
  input  [1:0] sel;
  output [3:0] x;
  reg    [3:0] x;

  always @(a or b or c or d or sel)
    begin
      case (sel)
        2'b00 : x = a;
        2'b01 : x = b;
        2'b10 : x = c;
        2'b11 : x = d;
      endcase
    end
endmodule
```

- 두 모듈은 같은 멀티플렉서를 기술하며, 둘 다 다섯 입력을 모두 이벤트 목록에 넣는다.
- `case` 버전이 더 짧고 진리표처럼 읽힌다. 합성 도구는 보통 `case`로부터 병렬 멀티플렉서를 만들고, `if-else if` 연쇄로부터는 우선순위 구조를 만든다(다만 여기서는 조건이 서로 배타적이므로 결과가 같다).

### 10.10 function 문

`function`은 소프트웨어의 함수처럼 반복해서 사용하는 계산을 하나로 묶는다.

```verilog
function [범위] function_이름;
  // 입력 선언
  // 처리문
endfunction
```

**규칙:**

- 반환값의 범위를 지정하지 않으면 **1비트**로 반환한다.
- 반환값은 **function 이름**으로 반환한다. 즉, 결과를 function과 같은 이름의 변수에 대입한다.
- function 내의 처리문에서 둘 이상의 문장을 사용하려면 `begin ~ end` 블록으로 둘러싸야 한다.
- function 내에 선언된 지역(local) 변수는 일시적인 것으로 취급되며 wire로 합성된다.
- function 정의는 module 안에 있어야 하며, **타이밍을 정의하는 문장**(`#` 지연, `@` 이벤트 등)을 **포함할 수 없다**.
- function은 순차 처리문에서 사용하는 `task`를 사용할 수 없는 반면, task에서는 function을 사용할 수 있다.
- function 안에서 `reg`, `parameter`, `integer` 등을 선언할 수 있다.

**입력 선언:**

- 입력은 **function 이름 다음에 바로** `input [범위] 입력 변수, ..., 입력 변수;`의 형식으로 선언한다.
- `[범위]`는 벡터일 경우에만 사용한다.
- function 호출에서 인수는 **입력이 선언된 순서대로** function 내의 입력 변수에 전달된다.

**function 호출 방법:**

- 형식: `네트 = function_이름(인수 이름, ..., 인수 이름);`
- 모듈의 인수 이름과 function의 입력 이름이 같을 필요는 없으나, **기술된 순서로** 대응한다.
- 출력은 function 이름에 할당되며, **출력은 한 개**(비트 또는 벡터)만 가진다.
- 결합 연산자 `{ }`를 사용하면 여러 개의 출력을 하나의 벡터로 묶어서 함께 리턴할 수 있다.

**예제: function으로 구현한 XOR.**

```verilog
/* XOR 함수를 "function" 문으로 사용한 경우 */
module EXOR (IN1, IN2, OUT);
  input  IN1, IN2;
  output OUT;

  function EXOR_FUNC;          // function 이름
    input IN1, IN2;
    if (IN1 ^ IN2)             // (IN1 XOR IN2) 결과가 "1"이면 실행
      EXOR_FUNC = 1;           // function 이름으로 리턴
    else                       // (IN1 XOR IN2) 결과가 "0"이면 실행
      EXOR_FUNC = 0;           // function 이름으로 리턴
  endfunction

  assign OUT = EXOR_FUNC(IN1, IN2);  // function 호출
endmodule
```

- function `EXOR_FUNC`에는 범위가 없으므로 1비트를 반환한다.
- `assign OUT = EXOR_FUNC(IN1, IN2);`는 function을 연속적으로 호출하므로, `OUT`은 항상 두 입력의 XOR와 같다.

> **참고:** 슬라이드의 모듈 헤더 `module EXOR (IN1, IN2, OUT)`에는 세미콜론이 없으므로 위에서 추가하였다. 슬라이드의 구문 형식에는 "function"이 "fucntion", "functuion"으로도 표기되어 있는데, 이는 오타이다.

## 11. 연산자

연산자 슬라이드는 먼저 8절의 게이트 원시 함수 표(`and`, `or`, `nand`, `nor`, `xor`, `xnor`, `buf`, `not`, `bufif1`, `bufif0`, `notif1`, `notif0`)를 반복한다. 이어서 식에 쓰는 연산자가 나온다.

### 11.1 산술 연산자

| 연산자 | 내용 |
|:--------:|:--------|
| `+` | 덧셈 |
| `-` | 뺄셈 |
| `-` | 음수 기호(단항 마이너스) |
| `*` | 곱셈 |
| `/` | 나눗셈 |
| `%` | 나머지 |
| `**` | 제곱승(거듭제곱) |

- `reg`, `wire`형의 피연산자는 **unsigned**로 취급된다.
- 피연산자에 알 수 없는 값(`x`)의 비트가 있으면 결과도 알 수 없는 값이다.

### 11.2 관계 연산자와 등가 연산자

| 연산자 | 내용 | 비고 |
|:--------:|:--------|:--------|
| `>` | 크다 | `reg`, `wire`형은 unsigned, `real`, `integer`형은 signed이며, 피연산자가 `x` 값의 비트를 포함하면 결과는 unknown이다. |
| `<` | 작다 | 위와 같음 |
| `>=` | 크거나 같다 | 위와 같음 |
| `<=` | 작거나 같다 | 위와 같음 |
| `==` | 같다 | 피연산자 중에 `x`가 있으면 결과는 무조건 unknown(`x`)이다. |
| `!=` | 같지 않다 | 위와 같음 |
| `===` | A === B이면 true(case 등가) | `z`, `x` 값을 포함하더라도 비트 단위로 정확하게 비교한다. |
| `!==` | A !== B이면 true(case 부등가) | 위와 같음 |

- `4'b10x0 == 4'b10x0`은 `x`(unknown)이지만, `4'b10x0 === 4'b10x0`은 1(참)이다. `===`는 `x`와 `z`를 비교할 평범한 기호로 취급하기 때문이다.
- `<=`는 "작거나 같다" 연산자이면서 논블로킹 대입 연산자이기도 하며, 의미는 문맥으로 결정된다.

### 11.3 논리 연산자와 시프트 연산자

**논리 연산자**는 각 피연산자를 하나의 참(0이 아님) 또는 거짓(0) 값으로 취급한다.

| 연산자 | 의미 | 예 |
|:--------:|:--------|:--------|
| `&&` | 논리 AND | `if (A && B) ...` |
| `\|\|` | 논리 OR | `if (A \|\| B) ...` |
| `!` | 논리 NOT | `if (!A) ...` |

**시프트 연산자**는 벡터의 비트를 이동시킨다.

| 연산자 | 의미 | 예(8비트) |
|:--------:|:--------|:-----------------|
| `>>` | 오른쪽으로 이동 | `1011_0011 >> 1`은 `0101_1001` |
| `<<` | 왼쪽으로 이동 | `1011_0011 << 1`은 `0110_0110` |

밀려 나간 비트는 사라지고, 빈자리는 0으로 채워진다. `1011_0011`의 언더바는 눈으로 보기 위한 구분자일 뿐이다.

### 11.4 비트 단위 연산자

비트 단위 연산자는 **서로 대응하는 비트끼리** 연산한다.

| 연산자 | 내용 | 비고 |
|:--------:|:--------|:--------|
| `~` | 각각의 비트에 not 연산 | |
| `&` | 각각의 비트에 and 연산 | |
| `\|` | 각각의 비트에 or 연산 | |
| `^` | 각각의 비트에 xor 연산 | |
| `^~`, `~^` | 각각의 비트에 xnor 연산 | |
| `<<` | `a << b`: a를 b비트 수만큼 왼쪽으로 시프트 | |
| `>>` | `a >> b`: a를 b비트 수만큼 오른쪽으로 시프트 | |
| `>>>` | `a >>> b`: a를 b비트 수만큼 오른쪽으로 시프트(산술) | a가 signed 타입이면 원래 a의 부호가 바뀌지 않도록 빈자리를 a의 부호 비트 값으로 채운다. |
| `<<<` | `a <<< b`: a를 b비트 수만큼 왼쪽으로 시프트(산술) | 위와 같음(아래 참고) |

> **참고:** 슬라이드는 시프트 행을 "a<b"로 표기하는데, 의도한 식은 `a << b`, `a >> b`, `a >>> b`, `a <<< b`이다. 또한 부호 비트로 채우는 규칙은 산술 **오른쪽** 시프트 `>>>`에만 적용된다. 산술 왼쪽 시프트 `<<<`는 `<<`와 똑같이 빈 하위 비트를 항상 0으로 채운다. 예를 들어 `reg signed [7:0] a = -8;`(1111_1000)이면 `a >>> 1`은 1111_1100(-4)이고, `a >> 1`은 0111_1100(124)이다.

### 11.5 축약 연산자

**단항 축약(unary reduction)** 연산자는 **피연산자 하나의 모든 비트**에 연산을 적용하여 **1비트** 결과를 만든다.

| 연산자 | 내용 |
|:--------:|:--------|
| `&` | 피연산자의 모든 비트를 and 연산해서 1비트짜리 결과 생성 |
| `\|` | 피연산자의 모든 비트를 or 연산해서 1비트짜리 결과 생성 |
| `^` | 피연산자의 모든 비트를 xor 연산해서 1비트짜리 결과 생성 |
| `~&` | 피연산자의 모든 비트를 nand 연산해서 1비트짜리 결과 생성 |
| `~\|` | 피연산자의 모든 비트를 nor 연산해서 1비트짜리 결과 생성 |

```verilog
reg [3:0] v;
reg a, b;
v = 4'b1101;
a = &v;      // a = 1 & 1 & 0 & 1 = 0
b = |v;      // b = 1 | 1 | 0 | 1 = 1
```

- 축약 AND `&v`는 v의 모든 비트가 1일 때만 1이며, "모든 비트가 1인가?"에 답한다.
- 축약 OR `|v`는 어느 한 비트라도 1이면 1이며, "v가 0이 아닌가?"에 답한다.
- 축약 XOR `^v`는 v의 패리티를 준다. 1101이면 1 ⊕ 1 ⊕ 0 ⊕ 1 = 1이다.

> **참고:** 슬라이드는 축약 NAND 연산자를 `&~`로 표기하지만, 올바른 Verilog 연산자는 `~&`이다.

### 11.6 결합 연산자와 조건 연산자

| 연산자 | 내용 |
|:--------:|:--------|
| `{ , }` | 좌우의 피연산자 값을 하나로 이어 붙인다(결합). |
| `? :` | `con ? a : b`는 con이 true이면 a, false이면 b이다(조건). |

**결합의 예:**

- `{a, b, c}`: a, b, c를 하나로 연결하여 긴 길이의 값을 만든다.
- `{a, 4'b1100}`: a 뒤에 1100 비트를 추가한다.

**반복의 예:** 중괄호 앞의 수는 내용을 반복한다.

- `{a, {3{b}}}`는 `{a, b, b, b}`와 같다.
- `{3{a, b}}`는 `{a, b, a, b, a, b}`와 같다.

조건 연산자로는 2x1 멀티플렉서를 한 줄로 기술할 수 있다: `assign y = sel ? d1 : d0;`

### 11.7 연산자 우선순위

우선순위가 가장 높은 것(먼저 계산)부터 가장 낮은 것 순서로 나열하면 다음과 같다.

| 우선순위 | 연산자 | 설명 |
|:--------:|:---------|:------------|
| 1(최고) | `[ ]` | 벡터에서 비트 단위 혹은 일부분 선택 |
| 2 | `( )` | 괄호 |
| 3 | `!`, `~` | 논리적, 비트 단위 NOT |
| 4 | `&`, `\|`, `~&`, `~\|`, `^`, `~^`, `^~` | 비트 단항 논리 연산자 |
| 5 | `+`, `-` | 부호 |
| 6 | `{ }` | 연결 연산자 |
| 7 | `*`, `/`, `%` | 산술 연산자(곱셈 계열) |
| 8 | `+`, `-` | 산술 연산자(덧셈 계열) |
| 9 | `<<`, `>>` | 시프트 연산자 |
| 10 | `>`, `>=`, `<`, `<=` | 관계 연산자 |
| 11 | `==`, `!=` | 논리적으로 같음/같지 않음 |
| 12 | `&` | 비트 처리 AND |
| 13 | `^`, `^~`, `~^` | 비트 처리 XOR, XNOR |
| 14 | `\|` | 비트 처리 OR |
| 15 | `&&` | 논리적 AND |
| 16 | `\|\|` | 논리적 OR |
| 17(최저) | `? :` | 조건 연산자 |

> **시험 팁:** 헷갈리면 괄호를 쓴다. 예를 들어 `a & b == c`는 `==`가 비트 단위 `&`보다 우선순위가 높으므로 `a & (b == c)`로 계산되며, 이는 대개 의도한 것이 아니다.

> **[C프로그래밍]** Verilog 연산자 대부분은 C 연산자와 모양이 똑같고 우선순위도 비슷하다. 차이점은 중요하다. Verilog에는 4값 논리(0, 1, x, z)가 있어서 `===`와 `!==` 연산자가 추가로 있고, C에는 없는 단항 축약 연산자(`&v`, `|v`, `^v`)가 있으며, 결합 `{ }`와 반복이 있고, 고전적인 Verilog-2001에는 `++`나 `+=` 연산자가 없다. C와 마찬가지로 `&&`와 `!`는 논리 연산자이고 `&`와 `~`는 비트 단위 연산자이며, 둘을 혼동하는 것은 흔한 버그이다.

## 12. Verilog 모듈 요약

![그림 14. Verilog HDL 모듈 구성 요소의 요약 (슬라이드 66)](../images/L05_p66.png)

*그림 14. Verilog HDL 모듈 구성 요소의 요약 (슬라이드 66)*

그림은 모듈 안에 들어갈 수 있는 것과 각 위치에 허용되는 데이터형을 요약한다.

- **포트:**
  - `input` 포트는 외부에서 `wire`나 `reg`로 구동할 수 있지만, 모듈 안에서는 `wire`이다.
  - `output` 포트는 모듈 안에서 `wire`나 `reg`일 수 있지만, 외부에서는 `wire`에 연결된다.
  - `inout` 포트는 양쪽 모두 `wire`이다.
- **모듈 인스턴스**(`Module_instance_A`, `Module_instance_B`): 출력은 `wire`에 연결되어야 하며, 각 인스턴스 안에서도 같은 포트 규칙이 다시 적용된다.
- **프리미티브 인스턴스화(Primitive instantiation):** (그림의 NAND와 인버터처럼) `wire`로 연결된 내장 게이트이다.
- **연속 대입(Continuous assignment):** `assign wire_A = C | D;`는 `wire`를 구동한다.
- **동작(Behaviors):** `always` 블록(Behavior_1)과 `initial` 블록(Behavior_2)은 **레지스터 변수**(`reg`)에 값을 대입한다.
- **선언(Declarations):** `reg reg_A, reg_B, ...;`와 `integer int_A, ...;`

> **핵심:** 가장 유용한 규칙 하나는 다음과 같다. `assign`으로 대입하거나 인스턴스 출력이 구동하는 신호는 **`wire`** 여야 하고, `always`나 `initial` 안에서 대입하는 신호는 **`reg`** 여야 한다.

## 13. 테스트벤치

### 13.1 테스트벤치의 목적

- **테스트벤치(test bench)** 는 Verilog HDL로 설계한 회로를 검증하기 위한 목적으로 **시뮬레이션 패턴(입력 자극, input stimulus)** 을 서술하는 Verilog 코드이다.
- 테스트벤치 구문은 IEEE 표준에 정식 등록되어 있다.
- 따라서 같은 테스트벤치를 다른 시뮬레이터에서도 공동으로 사용할 수 있다.

테스트벤치는 **포트가 없는** 모듈이다. 검증할 설계를 인스턴스화하고, 그 입력을 `reg` 신호로 구동하고, 출력을 `wire` 신호로 관찰하며, 시스템 태스크로 출력하거나 멈춘다.

### 13.2 주요 시스템 태스크와 함수

| 태스크 / 함수 | 설명 |
|:----------------|:------------|
| `$stop` | 시뮬레이션을 일시 정지시킨다. |
| `$finish` | 시뮬레이션을 완전히 종료한다. |
| `$display` | 실행될 때 변수, 수식, 값, 문자열을 **한 번** 출력한다. |
| `$monitor` | `$display`처럼 출력하지만, 출력하는 변수 중 하나라도 바뀔 **때마다 다시** 실행된다. |
| `$monitoroff` | `$monitor`의 실행을 잠시 중지한다. |
| `$monitoron` | `$monitor`의 실행을 재개한다. |
| `$strobe` | `$display`와 비슷하지만, 현재 시간 단계에서 항상 **가장 나중에** 실행된다. |
| `$time` | 현재 시뮬레이션 시간을 반환하는 시스템 함수이다. |

> **참고:** 슬라이드에는 `$monitoron`이 `$monitor`의 실행을 잠시 중지하고 `$monitoroff`가 재개한다고 되어 있는데, 이는 반대로 적힌 것이다. 이름 그대로 `$monitoroff`가 모니터링을 끄고 `$monitoron`이 다시 켠다.

**`$display`와 `$strobe`의 차이:** 여러 문장이 같은 시뮬레이션 시간에 실행될 때, `$display`가 그 문장들과 비교하여 어느 순서에 실행될지는 정해져 있지 않으므로 값이 갱신되기 전에 출력할 수도 있다. `$strobe`는 그 시간 단계의 다른 모든 이벤트가 끝난 뒤에 항상 실행되므로, 최종적으로 안정된 값을 출력한다.

**`$display`의 출력 포맷**(`$monitor`와 `$strobe`에도 사용):

| 포맷 | 출력 |
|:------:|:-------|
| `%d`, `%D` | 십진수 형식으로 값 출력 |
| `%t`, `%T` | 시간 형식으로 출력 |
| `%s`, `%S` | 문자열 |
| `%f`, `%F` | 실수값 형식으로 출력 |
| `%c`, `%C` | 1개 문자 출력 |
| `%h`, `%H` | 16진수 형식으로 출력 |
| `%o`, `%O` | 8진수 형식으로 출력 |
| `%b`, `%B` | 2진수 형식으로 출력 |
| `%m`, `%M` | 실행 모듈의 계층적 이름 출력 |

### 13.3 완전한 테스트벤치 예제

이 강의의 요소들을 종합한 다음 테스트벤치는 네 가지 입력 조합을 모두 가하여 9절의 반가산기 `HADD`를 검증한다.

```verilog
`timescale 1ns / 1ns
module tb_HADD;            // 테스트벤치에는 포트가 없다
  reg  in1, in2;           // 설계의 입력: 테스트벤치가 구동한다
  wire C, S;               // 설계의 출력: 관찰한다

  HADD dut (.C(C), .S(S), .in1(in1), .in2(in2));   // 검증 대상 설계

  initial begin
    $monitor("time=%0t in1=%b in2=%b -> C=%b S=%b", $time, in1, in2, C, S);
    in1 = 0; in2 = 0;
    #10 in1 = 0; in2 = 1;
    #10 in1 = 1; in2 = 0;
    #10 in1 = 1; in2 = 1;
    #10 $finish;
  end
endmodule
```

기대 출력은 다음과 같으며, 값이 바뀔 때마다 한 줄씩 출력된다.

```plaintext
time=0 in1=0 in2=0 -> C=0 S=0
time=10 in1=0 in2=1 -> C=0 S=1
time=20 in1=1 in2=0 -> C=0 S=1
time=30 in1=1 in2=1 -> C=1 S=0
```

출력된 값이 반가산기의 진리표와 일치하므로 설계가 검증된다. "인스턴스화하고, 시간에 따라 입력을 구동하고, 출력을 관찰한다"는 같은 패턴을 실습의 모든 설계에 사용한다.

## 요약

| 개념 | 핵심 요약 |
|:--------|:------------|
| 설계 흐름 | 명세 → 동작 기술 → RTL(HDL) → 기능 검증 → 합성 → 넷리스트 → 논리 검증 → 배치 배선 → 레이아웃 → 구현 순서이다. |
| FPGA | LUT와 D 플립플롭으로 된 기본 셀로 이루어지며, 다시 프로그래밍할 수 있어 시제품 제작에 이상적이다. PROM, PLA, PAL, CPLD는 더 단순한 프로그래머블 소자이다. |
| HDL의 장점 | 설계 시간 단축, 품질 향상, 기술 독립성, 비용 절감, 표준화, 쉬운 관리이다. |
| 모듈 | `module 이름(포트); ... endmodule`이며, 헤더는 `;`로 끝나고 `endmodule`에는 없으며, 식별자는 대소문자를 구별한다. |
| 데이터형 | 넷(`wire` 등)은 연결하고, 변수(`reg`, `integer`)는 저장하며, 값은 0, 1, X, Z이고, 상수는 `길이'진수 값` 형식이다. |
| 인스턴스 | 순서 또는 이름으로 포트를 연결하며, 파라미터는 `#( )`로 재정의한다. |
| 모델링 방식 | 게이트 수준(원시 함수), RTL 또는 데이터플로(`assign`), 동작적(`initial`, `always`, `if`, `case`, `function`)이다. |
| always | 이벤트가 필요하고, 대입되는 신호는 `reg`이며, 조합 논리에는 `@*` 또는 완전한 이벤트 목록을, 플립플롭에는 `posedge`/`negedge`를 사용한다. |
| 블로킹과 논블로킹 | `=`는 순서대로 실행되고(조합회로), `<=`는 한꺼번에 갱신된다(순차회로). |
| 연산자 | 산술, 관계, 등가(`==`와 `===`), 논리, 비트 단위, 축약, 시프트, 결합, 조건 연산자가 있으며, 우선순위가 정해져 있다. |
| 테스트벤치 | 입력을 구동하고 `$display`, `$monitor`, `$strobe`, `$time`, `$finish`로 출력을 확인하는 포트 없는 모듈이다. |

## 점검 문제

1. **설계 흐름:** 설계 흐름에서 기능 검증과 논리 검증의 차이는 무엇인가?

   > **정답:** 기능 검증은 합성 전에 RTL 기술을 테스트벤치로 시뮬레이션하여 기술한 동작이 올바른지 확인한다. 논리 검증은 합성으로 만든 게이트 수준 넷리스트를 같은 테스트벤치로 시뮬레이션하여, 합성이 동작을 그대로 보존했는지 확인한다.

2. **FPGA:** FPGA는 어떻게 기본 셀 하나로 4변수의 어떤 부울 함수든 구현할 수 있는가?

   > **정답:** 각 기본 셀에는 LUT(look-up table)가 들어 있다. 4입력 LUT는 네 입력을 주소로 하는 16비트 메모리이므로, 함수 진리표의 16개 출력값을 저장하면 그 네 변수의 어떤 함수든 구현할 수 있다.

3. **wire와 reg:** 어떤 모듈에서 신호 `y`는 `assign y = a & b;`로 대입되고, 신호 `z`는 `always @*` 안에서 대입된다. 각각 어떻게 선언해야 하는가?

   > **정답:** `y`는 연속 대입으로 구동되므로 `wire`여야 한다. `z`는 `always` 블록에서 대입되므로, 나타내는 논리가 조합 논리이더라도 `reg`로 선언해야 한다.

4. **파라미터:** `modXnor #(4, 5) G2 (y2_out, b2, c2);`는 무엇을 뜻하는가?

   > **정답:** 모듈 modXnor의 인스턴스 G2를 만들고, 파라미터를 선언 순서대로 size = 4, delay = 5로 재정의한다는 뜻이다. 따라서 G2는 입력이 바뀐 뒤 5 시간 단위 후에 출력이 바뀌는 4비트 XNOR이다.

5. **initial의 시간:** `#5 a = 1; #25 b = 0;`이 들어 있는 `initial` 블록에서 a와 b는 언제 대입되는가?

   > **정답:** 한 블록 안의 지연은 누적되므로, a는 5에, b는 5 + 25 = 30 시간 단위에 대입된다.

6. **블로킹과 논블로킹:** A = 5, B = 3, C = 10, D = 2일 때, 클록 에지에서 `A = D; C = B; B = A;`와 `A <= D; C <= B; B <= A;`의 결과는 각각 무엇인가?

   > **정답:** 블로킹: A = 2, 그다음 C = 3, 그다음 B가 새 A를 읽어 B = 2이다(결과 A = 2, B = 2, C = 3). 논블로킹: 모든 오른쪽 식이 이전 값을 사용하므로 A = 2, C = 3, B = 5이다(결과 A = 2, B = 5, C = 3).

7. **등가 연산자:** `==`와 `===`의 차이는 무엇인가?

   > **정답:** `==`는 논리 등가로, 피연산자 중 하나라도 x(또는 z)를 포함하면 결과가 x이다. `===`는 case 등가로, x와 z까지 포함하여 피연산자를 비트 단위로 비교하며 항상 0 또는 1을 반환한다.

8. **축약 연산자:** `v = 4'b1101`일 때 `&v`, `|v`, `^v`는 각각 무엇인가?

   > **정답:** `&v` = 1 & 1 & 0 & 1 = 0, `|v` = 1 | 1 | 0 | 1 = 1, `^v` = 1 ^ 1 ^ 0 ^ 1 = 1이다.

9. **카운터:** 2, 3, 4, 7, 8, 10, 11을 순환하는 카운터에서 클록 주기 도중에 `reset`이 0으로 떨어지면 어떻게 되며, 그 이유는 무엇인가?

   > **정답:** `always` 블록의 이벤트 목록에 `negedge reset`이 있으므로, 다음 클록 에지를 기다리지 않고 카운터가 즉시 2로 설정된다. 이것이 비동기식 액티브 로우 리셋이다.

10. **테스트벤치:** `$display`와 `$monitor`의 차이는 무엇인가?

    > **정답:** `$display`는 문장이 실행될 때 인수를 한 번 출력한다. `$monitor`는 한 번 설정해 두면 시뮬레이션이 끝나거나 `$monitoroff`가 실행될 때까지, 인수 중 하나라도 바뀔 때마다 자동으로 다시 출력한다.
